# 情境、时间线与调查

用于模组骨架、剧情依赖、势力行动和线索设计。先选择与用户体验相符的结构，再制作内容。

## 从构想到结构

用简短因果链辨认局势：过去发生了什么、现在谁想改变什么、玩家为何接触得到、哪些条件会改变局势。主持人应早知道运行所需的真相；玩家的信息通过行动获得，不能把面向读者的悬念写成主持人也不知道的裁定依据。

按需求选择：

| 形态 | 准备重点 | 常见薄弱处 |
| --- | --- | --- |
| 线性或限时短团 | 开场约定、明确转场、关键选择和应变 | 把预计的玩家反应当作转场条件 |
| 中心据点与外出 | 可访问地点、来回成本、据点变化 | 地点只列名称，没有参与内容 |
| 节点调查 | 事实、证据、解释、节点之间的可发现联系 | 一条线索或一次检定截断全部进展 |
| 沙盒与势力 | 地点、资源、目标、行动条件和反馈 | 把大量背景误当成可玩的内容 |
| 日常与关系 | 可接近的人物、共同活动、回应和后续回响 | 只有作者预期的温馨画面 |

组合结构可用，不要求统一成一种。单场细节必须有入口，但入口可以是已约定的共同生活或眼前活动，不必新增使命或强迫的求助。

## 准备情境

对当前范围有用时，写清人物或势力的目标、现有资源、权限、正在做的事、何时行动，以及何种事实让其改变做法。预备“如果无人干预”的发展，不能在玩家介入后仍照搬整张预设时间表。

把时间条件分为：

- 固定外部条件，例如列车发车、潮汐、已决定的会议。
- 人物计划，例如打算午夜偷走文件，可能因守卫或玩家变化而调整。
- 条件触发，例如警报响起才增援。
- 尚待作者决定的安排，例如新增支线是否延后一场聚会。

改动时间线时沿依赖检查：人物是否已到场、信息是否已获得、旅行耗时、物品归属、休整与规则资源、后续事件是否仍有成立条件。只修改受影响接口，其他地方保持原状。可用“原安排／新安排／连带影响”表提供可审阅的改动。

## 调查的信息设计

先列玩家必须得出的结论，再写可以支持它的证据。分清：

- **客观事实**：世界中实际发生的事。
- **证据**：角色可以通过某种行动接触到的痕迹、记录或证词。
- **解释**：证据支持的判断，未必唯一。
- **行动联系**：知道后能去哪里、问谁、查什么或作何决定。

关键结论通常需要冗余渠道。The Alexandrian的三线索法可作为起点：为必需结论准备至少三条线索，但实际按模组体量与系统设计调整。渠道应有不同获得方式，不只是三次相同检定。非关键发现不必一律满足数量。

区分自动获得的可见事实、主动行动后可获得的信息和按规则检定的部分。进入开放档案室通常能够看到公开日期；发现刮除的页码、判断墨水年代或偷取封存原件可能另有条件。玩家发现线索不等于已经正确解释，主持人不要直接替他们宣布推理结果。

检查失败是否封死必需路径。修复可以是提供独立证据、可付出代价的替代行动、允许故事沿失败局势发展，或按系统规定给予基本信息及额外发现。不能把“失败推进”当作所有系统中失败必得同一线索的规则。代价必须来自局势，不能临时惩罚玩家没有找到预设答案。

红鲱鱼若有意义，需要真实的误解来源、可辨别依据与有边界的查证成本；不要仅为消耗桌上时间放置无回报的假线索。

## 一个简短的调查样例

目标是查明仓库为何在停电前已清空。值班簿有下午的提货时间；门卫见过挂错号牌的货车；附近店铺账单记录司机买饭的时刻。分别支持“清空发生在停电前”，但不能单独证明谁策划了停电。

玩家翻公开簿册可直接得知提货时间。门卫不信任陌生人，是否说明车牌取决于交涉及当前规则。玩家交涉失败仍可查附近店铺，或转而追查仓库管理者；若他们放弃，幕后货车按已设定路线离开，不凭空出现在玩家下一站。
