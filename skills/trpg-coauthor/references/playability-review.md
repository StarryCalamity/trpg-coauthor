# 运行审查与设计推演

用于完成前检查或对现有模组评审。按实际风险选择检查，不要求每个小片段填写全部项目。

## 从一次真实行动开始

选择当前场景中合理的玩家行动，从主持人给出感知信息开始，依次推演行动声明、NPC或环境回应、必要规则、局势变化和收束。若主持人必须临时补关键事实才接得下去，补足该事实或明确其可即兴范围。

不要只选设计最希望发生的行为。找最可能使设计失效的一个或几个情况，再推演：

| 情况 | 要检查的地方 |
| --- | --- |
| 不参与、离开、换话题 | 场景能否收束，其他活动与时间怎样继续 |
| 失败或解释错误 | 后果是否合理，核心路径是否全被封死 |
| 提前行动、顺序颠倒 | 人物知识、物品与时间条件是否仍成立 |
| 意外但可行的方法 | 主持人是否能据局势裁定，而非拒绝非预设答案 |
| 怀疑、冷淡或敌意 | NPC反应是否与已知动机和权限一致 |
| 只有一人发言或分开行动 | 其他玩家是否还有参与机会，信息如何流动 |
| 时间不足 | 哪些部分可概述、跳过或留待之后，关键条件如何交接 |

修复发现的断点，再检查直接受影响的部分。没有新问题时完成交付，不固定反思轮数，不穷举所有可能行动。

## 判断问题的严重程度

优先修复无法进入、无法裁定、关键事实冲突、必须依赖玩家特定选择或一次失败就无内容的断点。其次改善信息负担、互动机会和节奏。纯审美偏好与已成立的作者风格应分开，不能把所有不同于助手偏好的安排称为错误。

玩家可作选择不意味着作者必须为每种选择制作同等体量的新支线。主持人有反应依据、真实后果和转场方式即可。固定事件不等于强迫玩家行动；同样，表面多个选项也不能掩盖所有结果都被偷偷改成同一个。

## 连续性检查

关注当前变化影响的时间、地点、信息、物品、人物关系和资源。区分：

- 世界中存在与玩家已经接触。
- NPC知道与NPC愿意告诉。
- 玩家听到与角色相信。
- 人物想做与有权限或能力完成。
- 作者期待与游玩已经发生。

只有后一状态有具体依据时才更新。未来回响使用条件说明，不能提前把候选互动写成共同经历。

## 示例：修复一个薄弱转场

原设想：“玩家帮摊主画好招牌，摊主因此信任他们，带他们去秘密码头。”

断点是三次假定：玩家必帮助、帮忙必产生信任、该程度的信任足以公开秘密。修复时先看作者真正需要什么。若秘密码头是后续调查的必要节点，设置独立且合逻辑的获得渠道；若只是可选探索，则说明摊主透露信息的条件及拒绝后的其他活动。无需把日常改成必须完成的任务，也无需取消作者想写的码头。

## 验证表述

文字检查能够发现表达和连续性问题；设计推演能够发现一部分运行断点；规则核查能够确认特定条文或计算；实际带团才能提供玩家参与、节奏和情绪的观察。交付只报告实际做过的验证，未验证的方面明确说明，不将结构完整视作移情已成功。
