# trpg-coauthor设计推演记录

此记录位于技能包之外。验证方式是制作具体输出并人工推演，不是独立模型自动评测，也不是实际带团。结构验证由仓库维护脚本与GitHub Actions另行执行。

## 1. 安静的日常与拒绝参与

测试请求：在住院角色出院前设计一个轻松下午，让他们有机会认识隔壁病房的老人。无需主线线索，不给玩家安排任务。

读取路径：入口→日常与社交→NPC与对白→运行审查。

产物：

老人在公共休息室听一段旧广播，带了几本以前的杂志。桌上还有半壶热水。他想把收藏分给愿意读的人，但不把每本都送出去。玩家可以坐下、问广播内容、翻杂志、谈自己的兴趣，或经过后离开。

若玩家加入，他先问对方平时看什么，再按实际回答拿出一本；不凭空猜中玩家的爱好。不善言辞的玩家可以只说明“角色想聊几句”，主持人根据这一立场接话。普通聊天不用检定。若问起其过去工作，他愿谈值夜班的趣事；若追问病情，他说明现在不想谈。

休息室即将清洁时，老人收起剩余杂志。玩家实际借走一本时才建立归还约定；未借走则不产生该约定。玩家不参与时他继续听广播，整个下午可概述结束。

推演：一名玩家问工作、另一名玩家只看杂志，都有独立接触点；拒绝参与不会丢失必需情报；与老人关系是否变化依实际游玩而定。没有添加委托、突发危机、秘密或好感数值。结果：局势和收束可运行，移情未验证。

## 2. 调查失败及可选秘密

测试请求：修复“玩家必须说服邮差，得到一封旧信才能知道废站地址”的单点。旧信中的勒索证据仍应难以获取。

读取路径：入口→情境与调查→遭遇与规则→运行审查。

产物：

将“废站在哪里”和“旧信证明谁勒索了谁”分开。前者是必要联系，后者是可选证据。市镇旧地图标有站址；铁路退休员工知道旧站的俗称与行走路线；邮差认得信上的旧投递区。三条渠道分别来自公开记录、熟悉当地的人和邮政信息。

邮差负有保管责任，可告知旧投递区，未必交出原信。若获取原信的交涉按当前系统失败，失败保持有效；玩家仍能查地图或找铁路员工到达旧站。原信并不自动掉落，也不偷偷换到地图上。若玩家选择盗取，则需根据守卫、存放条件和当前规则另作裁定。

推演：交涉失败后，玩家有独立方式找到站址，但仍缺少勒索证据；完全放弃调查可以让幕后人物按已设定计划行动，不保证追回证据。结果：必要联系不被单次失败封死，同时保留可选发现的难度。具体系统裁定尚未给定，未编造检定名称或难度。

## 3. 潜台词与局部改稿

测试输入：人物愿意保护来客，但不能替他们办理通行证。原稿写“你们想走随时都能走”，与权限冲突；只改这句话，后面的日期和事件保持不变。

读取路径：入口→NPC与对白→文字与交付→运行审查。

修改产物：“申请我可以替你们递上去，通行证什么时候下来，要等办公室的答复。”

推演：这句话说明能够提供的帮助，不许诺无权决定的结果。人物可能确实希望来客安全离开，也可能同时维护秩序；未确定的心理不写成事实。玩家若要求保证，主持人依已确认权限回应；不另增逃亡剧情或改日期。结果：只修复已授权的对白边界。

## 4. 未指定系统的遭遇

测试请求：为四名角色做一个可谈判、可绕过的桥上阻拦，具体数值暂未指定系统。

产物：守桥者受路桥署委派收取修缮费，封住车道但保留单人步行通道。其账单确有工程来源；无权免除费用，但可为暂时无钱的旅人登记欠款。玩家能查看账单、交涉、寻找下游浅滩或强行突破。守桥者的目标是保住收费与秩序，面对明显失控的暴力会撤回值班屋呼救，无意战死守桥。这些是本次草案的常规设计细节，尚未成为用户项目设定。

推演：可以先完成空间、目标、替代行动与后果；制作等级、命中率和公平战力预算前需要系统及角色能力资料。结果：不会套用D&D数值，也不会因为缺少数值拒绝提供结构。此案例不验证遭遇平衡。

## 5. 激活边界与输入不足

| 请求 | 预期选择 | 人工检查 |
| --- | --- | --- |
| “帮我改模组这一场聚会” | 激活，读取原稿及社交方法 | 范围对应模组共同创作 |
| “这一段玩家什么都做不了，怎么改？” | 激活，先查原文与运行断点 | 不要求用户先填设定表 |
| “做一个有复杂潜台词的NPC” | 激活，NPC与对白 | 不把复杂性等同于秘密反派 |
| “写一首关于港口的诗” | 不因港口词汇激活 | 纯诗歌不属于本技能边界 |
| “现在直接主持游戏，我扮演玩家” | 识别为另一个工作流 | 本技能不默认切换为自动GM |
| “给我某系统的官方检定难度” | 查对应版本的一手规则 | 本包未自称附带官方规则库 |
| “设计一个平衡的最终Boss”，无系统资料 | 先做可独立的局势，并询问制作数值必需的信息 | 不捏造平衡保证 |

上述为触发描述和流程的人工审查，不证明平台自动路由在所有措辞下均正确。

## 发现及处理

旧版技能依赖相邻技能目录，并夹带特定项目与机器信息；新版将方法写入包内参考，移除这些依赖。固定线索数、句数、事件数、失败必得线索等上游建议改为有适用条件的方法。全部示例区分预期情绪与已发生的互动。

## 未验证部分

未进行跨模型盲测、长团运行或真实玩家反馈收集。此版本的验收范围是规范结构、离线资料完整性、打包可迁移性，以及以上具体设计推演。
